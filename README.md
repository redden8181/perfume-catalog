# Ароматека — личный каталог парфюмерии

Мобильное веб-приложение (PWA) для ведения собственной коллекции ароматов.
Данные вводятся вручную и хранятся **локально на вашем устройстве** — никакого
сервера, регистрации и внешних баз. Готово к автоматической публикации на
**GitHub Pages** через **GitHub Actions**.

## Возможности

- **Подбор по нотам** — главная функция. Выберите одну или несколько нот
  («Малина», «Мускус», «Ваниль»…) — каталог покажет только подходящие ароматы.
  Два режима:
  - **Содержит все ноты** (по умолчанию): «Малина + Мускус» → только ароматы,
    где есть ОБЕ ноты;
  - **Любую из нот**: достаточно одной совпавшей ноты.
- **Поиск** по названию, бренду и нотам одновременно.
- **Фильтры**: бренд, пол, год выпуска, минимальный рейтинг, «только избранное».
- **Карточка аромата**: фото, бренд, название, пол, год, пирамида нот
  (верх/сердце/база), описание, характеристики, рейтинг, личные заметки.
- **Интерактивные ноты**: нажатие на ноту со страницы аромата открывает каталог
  с уже применённым фильтром по этой ноте.
- **Ноты — единые сущности**: автодополнение «мал…» → «Малина»; «малина» и
  «Малина» никогда не станут двумя разными записями. Новые ноты и бренды
  создаются прямо из полей ввода.
- **Избранное** с отдельным разделом.
- **Личные заметки** («Купить позже», «Напоминает Dior Homme»…) — редактируются
  прямо на странице аромата.
- **Импорт / экспорт JSON** — полная резервная копия каталога в один файл и
  восстановление из него (с дедупликацией нот и брендов при импорте).
- **PWA для iPhone**: добавляется на домашний экран, открывается в полный
  экран (standalone), своя иконка и цветовая тема.
- **Mobile First**: крупные кнопки, нижняя навигация, шторки вместо модалок.
- Тёмная «парфюмерная» тема (архитектурно готова к светлой).

### Архитектурный принцип

UI ничего не знает о том, где лежат данные. Всё общение идёт через
`CatalogStorage` (`src/core/storage.ts`). Сейчас реализация —
`LocalCatalogStorage` (localStorage). Чтобы перейти на серверную базу,
достаточно реализовать тот же интерфейс поверх `fetch` (заготовка
`ApiCatalogStorage` уже есть) и поменять одну строку в `getCatalogStorage()`.

## Запуск локально

Требования: **Node.js 20+**.

```bash
npm ci          # установка зависимостей
npm run dev     # http://localhost:3000
```

При первом запуске каталог заполняется демо-данными — можно сразу
проверить фильтрацию:

| Выбранные ноты      | Результат                          |
| ------------------- | ---------------------------------- |
| «Малина»            | Framboise Nuit, Ambre Framboise    |
| «Малина» + «Мускус» | только Framboise Nuit              |
| «Мускус» + «Ваниль» | Framboise Nuit, Musc Vanille       |

Удалить демо-данные и вести только свою коллекцию: **Ещё → Очистить каталог**.

## Сборка

Обычная (серверная) сборка:

```bash
npm run build
npm start
```

Статическая сборка для GitHub Pages (как в CI):

```bash
STATIC_EXPORT=true NEXT_PUBLIC_BASE_PATH=/имя-репозитория npm run build
# результат — готовые статические файлы в каталоге out/
```

## Публикация на GitHub Pages (первый запуск)

1. Создайте **публичный** репозиторий на GitHub
   (на бесплатном тарифе Pages работает только в публичных) и запушьте код:

   ```bash
   git init
   git add .
   git commit -m "Ароматека: личный каталог парфюмерии"
   git branch -M main
   git remote add origin git@github.com:<ваш-логин>/<имя-репозитория>.git
   git push -u origin main
   ```

2. **Больше ничего нажимать не нужно.** Workflow `.github/workflows/deploy.yml`
   после каждого `git push`:
   - устанавливает зависимости (`npm ci`);
   - собирает статический сайт в `out/`;
   - публикует его в ветку `gh-pages`;
   - включает GitHub Pages через API, если он ещё не включён.

3. Через 1–2 минуты сайт доступен по адресу
   `https://<ваш-логин>.github.io/<имя-репозитория>/`.
   Точная ссылка также выводится в самом запуске (вкладка **Actions →
   последний запуск → Summary**) и в **Settings → Pages**.

4. Если сайт не появился за пару минут, включите Pages вручную один раз:
   **Settings → Pages → Build and deployment → Source: «Deploy from a branch»
   → Branch: `gh-pages`, папка `/(root)` → Save.**

Дальше достаточно менять код и делать `git push` — версия на сайте
обновляется сама. Вручную загружать файлы не нужно никогда.

### Если GitHub Actions не нужен: публикация за минуту

Это обычный статический сайт — его файлы можно разместить **где угодно**,
без workflow вообще:

```bash
STATIC_EXPORT=true npm run build   # соберёт готовый сайт в out/
```

Содержимое папки `out/` перетащите на любой статический хостинг:

- **Netlify Drop** — [app.netlify.com/drop](https://app.netlify.com/drop)
  (перетащили папку → сразу получили адрес сайта);
- **Vercel**, **Cloudflare Pages**, **GitHub Pages с загрузкой вручную** —
  тоже подойдут.

Технически сайт — это `index.html` + CSS/JS + картинки. Никакого сервера,
базы данных или «установки приложения» не требуется.

> Base path (`/<имя-репозитория>`) подставляется в сборку автоматически,
> включая особый случай репозитория `<логин>.github.io`.

## Установка на iPhone

Это обычный сайт — ничего устанавливать из App Store не нужно.

1. Откройте опубликованный сайт в Safari.
2. Нажмите «Поделиться» → **«На экран "Домой"»** → «Добавить».
3. Иконка «Ароматека» появится на домашнем экране и будет открывать сайт
   в отдельном окне без адресной строки — как обычное приложение
   (манифест и иконки уже настроены).

## Резервное копирование

**Ещё → Экспорт JSON** — скачивает весь каталог одним файлом
(ароматы + ноты + бренды + настройки). **Импорт JSON** — полностью
восстанавливает каталог из файла на любом устройстве. Экспортируйте
периодически: localStorage привязан к конкретному браузеру и устройству.

Фото флаконов при добавлении уменьшаются до 900px и хранятся внутри каталога
(data URL), поэтому они тоже попадают в экспорт.
